# 授权模式：个人免费，企业付费

## 一句话

**开源核心（MIT）永久免费，企业付费的是闭源扩展包 + 服务。**

## 为什么是这种模式（而不是换个更严的许可证）

一个常见误解是"把许可证改成 AGPL/BSL/SSPL 就能让企业交钱"。本项目不行，原因很具体：

1. 本项目是对原型 [LivingAi](https://github.com/speedyk-005/LivingAi)（MIT, © 2026 Speed K）的重写，
   保留了它的若干设计（工具定价表、磨损公式、`+40` 修复、技能衰退规则、LivingAI 人设与 6 个技能名）。
   这些部分受 Speed K 的 MIT 授权约束——**该授权对他授予的任何人都不可撤销**。
2. 因此我们不能对整个代码库单方面改成更严格的许可证（那等于收回第三方已授予的权利）。
3. **而且 MIT 发布本身不可撤销**：一旦以 MIT 发布，那个版本就永远可以被任何人免费使用
   （只需保留版权声明）。"先开源、以后再收费"这条路线在许可证层面走不通。

唯一在法律上干净、又能真正收到钱的做法：**开源核心 + 闭源企业扩展（open-core）**。
商业效果完全一样——个人免费用核心，企业需要付费功能就得买。

## 三层结构

| 层 | 许可证 | 内容 | 谁在用 |
|---|---|---|---|
| **核心（本仓库）** | **MIT** | Agent、复式账本、任务板、市场、技能、记忆、CLI、仪表盘、实验框架 | 个人 / 研究者 / 企业都能免费使用 |
| **企业扩展包** | **商业许可**（见 `LICENSE-ENTERPRISE`） | SSO/OIDC、RBAC、审计导出、多租户隔离、团队报表、SLA | 付费企业 |
| **服务** | 合同约定 | 托管、实施、培训、优先支持、定制 | 付费企业 |

## 企业版包含什么（`ARIA_LICENSE` 解锁）

| 功能 | 说明 |
|---|---|
| `sso` | 单点登录（SAML / OIDC），接入企业身份目录 |
| `rbac` | 角色与权限：谁能发任务、谁能看账本、谁能改配置 |
| `audit_export` | 全量复式账本导出 CSV/JSON（合规审计刚需） |
| `multi_tenant` | 多租户：按团队隔离钱包与账本，互不干扰 |

功能实现放在**私有包 `aria_enterprise`**；本开源仓库只含"集成点 + 许可校验"
（`aria/enterprise/`），所以开源版不含任何闭源代码。

## 我能怎么赚钱

- 卖许可证（按席位 × 年限）：`python scripts/issue_license.py --org "..." --seats 50 --days 365`
- 卖托管：代码 MIT，但"我帮你跑 + LLM 成本打包"是有偿服务
- 卖服务：实施、培训、定制、优先支持、SLA
- 卖品牌：MIT 不管商标，"Aria" 可作为品牌（建议注册商标）

## 客户怎么用

```bash
pip install aria-agent          # MIT 核心，免费
pip install aria-enterprise     # 私有索引，付费客户才有
export ARIA_LICENSE="ARIA1.eyJ..."   # 你签发的许可证
python -m aria                  # /license 可查看当前授权状态
```

## 我能收回免费版的权利吗

不能。MIT 授权不可撤销——**已经发出去的版本永远免费**。
将来想收费，只能靠**新增的闭源功能**，不能靠收回已有的开源代码。
所以策略是：**核心做薄、做稳、免费；增值能力做厚、闭源、收费。**
